# Skill package description

## 适用范围

本技能包用于成对的 Vivado SVPWM 工程：一个固定载波基线版，一个混沌或伪随机变载波实验版。主要任务是工程复现、BIT 溯源、资源与时序对比、测试方案制定、故障定位和竞赛工程包整理。

它不负责从 BIT 反编译完整源码，也不把仿真结果替代为实板数据。

## 技能项目

| 项目 | 文件 | 适用场景 | 使用方法 | 已验证效果 | 失效条件 |
|---|---|---|---|---|---|
| 提示词工作流 | references/prompt-workflows.md | 工程审计、复现、对比、故障分析、交付 | 选择对应模板并替换方括号字段 | 能让输入、证据等级和输出清单保持一致 | 用户未提供工程路径、板卡型号或目标任务 |
| 案例模板 | references/case-templates.md | 项目规格、测试记录、对比报告 | 复制模板并填写真实数据 | 避免遗漏工具版本、探头设置、哈希和时序数据 | 用估计值代替真实测试结果 |
| 工程验证脚本 | scripts/verify-project.ps1 | 检查 XPR、RTL、XDC、BIT、仿真与报告 | 传入工程根目录和可选 BIT 哈希 | 已在普通版与混沌版工程上识别全部关键文件并通过哈希校验 | 工程目录结构完全非标准且未显式提供 BIT 路径 |
| 报告对比脚本 | scripts/compare-vivado-reports.ps1 | 对比两个 Vivado 实现结果 | 传入两组 timing/utilization 报告 | 已提取 WNS、TNS、LUT、寄存器、BRAM、DSP | 报告不是 Vivado 文本格式或字段语言/格式发生变化 |
| 清单生成脚本 | scripts/make-manifest.ps1 | 发布前固定文件版本 | 对工程根目录生成 SHA-256 JSON | 可检测交付后源码、约束和 BIT 是否变化 | 文件在生成清单后继续修改 |
| 排错清单 | references/troubleshooting.md | 无 PWM、低电流、抖动、FFT 相似、工程打不开 | 按现象查找触发条件和排查顺序 | 覆盖本项目实际出现过的高频问题 | 驱动板硬件已损坏但没有独立电气检测 |
| 硬件安全边界 | references/hardware-safety.md | 烧录和上板测试 | 测试前逐项确认 | 防止自动启动 BIT、探头接地和逻辑电平造成额外风险 | 缺少独立关断、限流或电压兼容信息 |

## 经验来源

这些内容来自本项目中实际发生的失败与观察，包括：BIT 与源码版本混淆、驱动有效电平判断错误、三 PWM/六 PWM 接法不一致、万用表把 PWM 显示成稳定电压、普通版与混沌版 FFT 设置不一致、低电流且电机不转、开环低速抖动、自动启动 BIT 的烧录风险，以及 Vivado 工程和报告的可复现性整理。

## 推荐执行顺序

1. 用提示词工作流明确任务和输入。
2. 用工程验证脚本检查两个版本。
3. 运行仿真和 Vivado 实现。
4. 用报告对比脚本生成定量表格。
5. 按案例模板记录实板测试。
6. 用排错清单处理异常。
7. 用清单脚本固定交付版本。

每一步都要标明证据来自源码检查、仿真、Vivado 报告还是实板测量。
